# ADR-0005: Compaction Threshold for agnes-3.0-flash — Keep 0.2, Do Not Restore 0.7

**Status**: Accepted
**Date**: 2026-09-20
**Deciders**: Architecture Team (待评审), 用户提出「阈值是否应恢复到 0.7 以增强缓存率」

---

## Context

会话 `d503d810`（agnes-3.0-flash，100 次请求）实测：TTFT 均值 69.0s、中位 40.2s、**合计 6,896s（1.92 小时）**，
prompt 中位 328,795 token、峰值 438,042 token。已定位主因为**端点侧缓存未命中时的预填充成本**
（实测约 2.2K token/s，一次全 miss 需 100-176s）。

已应用整改：在 `cordis.patch.yml` 为 agnes 单独设置 `thresholdRatio: 0.2`（阈值 104,857 meter token），
使 prompt 峰值从 ~419K 降到 ~105K meter token。**用户随后提出反向质疑**：阈值过低会导致压缩频繁触发，
而每次压缩都会改写前缀、使端点缓存失效，从而**降低缓存命中率**——是否应恢复到 0.7？

该质疑在机制上成立（压缩确实改写前缀），因此必须用测量决定，而非直觉。

---

## Evidence

### 1. 全 miss 与 prompt 规模无关（否定"小 prompt 更易命中"与"大 prompt 更易 miss"两个方向）

`cacheRead < 20,000` 定义为全 miss，实测 **41/100 = 41%**。

| prompt 规模 | 步数 | 全 miss | 命中率 |
|---|---|---|---|
| <50K | 3 | 2 | 33.3% |
| 50-150K | 7 | 1 | 85.7% |
| 150-250K | 14 | 4 | 71.4% |
| 250-350K | 41 | 21 | 48.8% |
| >350K | 35 | 13 | 62.9% |

**皮尔逊相关 r(prompt 规模, miss) = -0.035**（≈ 0），且分桶非单调。
⇒ **prompt 大小既不提高也不降低命中率**；提高阈值买不到缓存率。

### 2. 全 miss 的成因是端点侧后端不一致，不是 TTL、不是重试

| 假设 | 检验 | 结论 |
|---|---|---|
| TTL 过期（人类思考间隔） | 间隔 <5s 的 88 步仍有 **37.5%** miss；>10min 的 8 步 87.5% miss | 仅解释 8 步 |
| `llm/retry` 导致 | 有重试 40.0% vs 无重试 41.1% = **-1.1pt** | 无关 |
| `todo/write` 导致 | 有 23.1% vs 无 43.7% = **-20.6pt** | 负相关 |
| turn 起始导致 | turn 首步 **66.7%** vs 中间步 37.5% = +29.2pt | 部分相关 |
| 前缀被改写导致 | prune 爆发前 `cacheRead=435,968` → 爆发后 **6,400**，随后 **3 步连续全 miss** | 确实有害，但样本仅 1 次爆发 |

**状态持续性**（关键）：

```
P(miss | 前一步 miss) = 26/41 = 63.4%
P(miss | 前一步 hit ) = 14/58 = 24.1%
P(hit  | 前一步 hit ) = 44/58 = 75.9%
```

miss 是**黏性**的（非随机、非交替）。且两类步的 `cacheRead` 取值截然不同：

- 命中步：`383,488` / `392,448` / `344,832` …（**完整会话前缀**被缓存）
- 全 miss 步：`6,400` / `7,936` / `7,680` / `3,584`（**只有共享的系统+工具块**被缓存）

同一 turn 内、间隔 <5s、前缀完全相同的情况下，会话在「缓存整个会话前缀的后端」与
「只缓存共享系统前缀的后端」之间切换，形成 5-6 步的交替段（如 turn 10 出现 `M h M h M h`）。
⇒ **部分后端根本不缓存会话级大前缀**（或缓存容量/写入策略不同）。这是端点侧缺陷，
**与阈值设置无关**。

### 3. 反事实模型（以实测 6,896s 校准，误差 1-13%）

模型：`miss 成本 = 真实峰值 × 0.62 / 2200 tok/s`；`hit 成本 = 21.9s`（实测中位，含排队与首 token 开销）；
`压缩开销 = 压缩次数 × (2 × miss 成本 + 15s 摘要生成)`；`真实 token = meter × 1.28`。

| 配置 | 阈值(meter) | 真实峰值 | 单次 miss | 基线 100 步 | 压缩开销 | **合计** |
|---|---|---|---|---|---|---|
| 现状 0.8 | 419,430 | 536,870 | 151.3s | 7,495s | 318s | **7,813s** |
| **恢复到 0.7** | 367,001 | 469,762 | 132.4s | 6,720s | 280s | **7,000s** |
| 折中 0.5 | 262,144 | 335,544 | 94.6s | 5,169s | 408s | **5,577s** |
| 0.3 | 157,286 | 201,326 | 56.7s | 3,618s | 385s | **4,004s** |
| **当前 0.2** | 104,857 | 134,217 | 37.8s | 2,843s | 453s | **3,296s** |

恢复 0.7 相比 0.2：**多花 3,704s（+112%）**，而命中率不变（证据 1）。

## Decision

1. **保持 `thresholdRatio: 0.2`，不恢复到 0.7。**
   理由：miss 率由端点后端路由决定且与规模无关（41%，r=-0.035），而 miss 成本与 prompt 规模成正比
   ——因此**缩小 prompt 是唯一可控的减损手段**。
2. **缓存率的提升走另一条杠杆：减少每步上下文增长**（而非提高阈值）。
   已交付精确检索工具 `docs/ai-workspace/tools/jqkj-search/`，把文档检索子任务从 413,998 字符降到约 8,500 字符。
   增长降低后，**任意阈值下压缩次数都减少**，从而同时获得「小 prompt」与「少改写」。
3. **压缩频率的代价已被计入并接受**：0.2 下约 4.6 次压缩/100 步（vs 0.7 的约 1 次），
   额外开销约 453s vs 280s（**+173s**），远小于每次 miss 省下的 94s × 41 步 ≈ 3,854s。
4. **向 Agnes AI 反馈端点缺陷**：同一会话在同一 turn 内、间隔 <5s、前缀相同，部分后端返回
   `cacheRead=6,400`（仅共享系统块）而另一些返回 `383,488`；miss 状态黏性 63.4%。
   请求核查后端前缀缓存的一致性/容量与粘性路由。
5. **重新评估触发条件**（满足任一即复审本 ADR）：
   - 端点修复后实测 miss 率降到 <10%；
   - 实测 miss 率变为**与 prompt 规模相关**（r 显著为正）；
   - agnes 的真实上下文窗口或预填充速率发生量级变化；
   - 精确检索工具落地后实测每步增长显著下降（届时阈值可上调以进一步减少改写）。

---

## Consequences

### Positive

- 每次不可避免的 miss 成本从 132-151s 降到 **38s（约 3.5×）**；
- 100 步总 TTFT 从实测 6,896s 预计降到约 **3,296s（-52%）**；
- 决策基于测量而非直觉，且给出了明确的复审条件。

### Negative

- 压缩触发更频繁（约 4.6 次/100 步）：每次伴随一次摘要生成调用与一次前缀失效（约 1-3 步 miss）；
- 长会话中摘要调用本身消耗 token 与时间（已计入 453s）；
- 本 ADR 的收益上界受端点 miss 率限制：**即使 prompt 降到 0，TTFT 地板仍约 2,150s（100 × 21.9s 命中开销）**，
  故 0.2 已接近当前端点条件下的可达下限。

### 被否决的备选

| 备选 | 否决理由 |
|---|---|
| 恢复到 0.7 | 命中率不变（r=-0.035），总时长 +3,704s |
| 折中 0.5 | 比 0.2 多 2,281s，命中率不变 |
| 完全关闭压缩（前缀永不变） | 即现状 0.8 附近，7,813s，最差 |
| 依赖粘性路由/缓存亲和 | 客户端不可控；已作为厂商反馈项 |

## 复审记录（2026-09-20 v5，同日 16:30）

**Decision 不变（保持 0.2）**，六条更新：

1. **「依赖粘性路由/缓存亲和＝客户端不可控」从推测升级为实测**：端点前置 `Server: cloudflare`，
   `CF-RAY *-CZX`；`api.agnes-ai.cn` 仅 1 条 anycast A 记录；同一 TCP 连接内 CF-RAY 尾部节点标识恒定
   （换连接才变）⇒ 客户端最多钉住**边缘节点**；而同连接、同 payload、间隔 45s 的复测在 16:1x 仍
   `cached_tokens=0`（14/14）⇒ 钉连接不能钉源站。被否决备选表中的这一条成立。
2. **判读口径需修正（不改结论方向）**：`cached_tokens` 单独作判据会误判——实测 112,085 tok 请求
   30.8s 完成（3,639 tok/s）却报 `cached=0`，同 payload 的 warm 用 214s。改用双判据
   （`cacheRead<20K` **且** `TTFT ≥ max(30s, 0.5×prompt/2244)`）后真 miss = **35/100**，
   本 ADR 的 41% 读作**上界**；证据 1（r=-0.035，规模无关）在双判据下更强：同一 header 世代 gen1
   （n=71，prompt 161K–438K）内 r(prompt, 真miss) = **+0.039**。
3. **链式机制确认（支撑本 ADR 的压缩代价核算）**：命中步 `cached(k) ≈ prompt(k-1)`，失配中位 **−0.55%**；
   `cacheRead` **100/100 步为 256 整数倍** ⇒ 分块严格前缀缓存，任何前部改写（压缩/prune/就地替换）击穿全段。
   同时 miss 步残值在同一世代内出现 `2,304` 与 `7,936` 两档（都小于 26 工具定义块 28,496 字符 ≈ 7.1–9.2K tok）
   ⇒ 分歧点不固定在客户端可解释的位置，进一步指向后端条目残留差异。
4. **阈值寻优（同公式复现本 ADR 表格，误差 ≤5%）**：`0.06/4096` 预测 2,214s、`0.05/3072` 预测 2,166s
   （当前 `0.2/32768` 3,260s），**−32~−34%**；但敏感性检验表明该收益**完全来自 41% 的 miss**
   （miss 5% → −5.0%，miss 0% → −0.8%），代价是每 5–8 步一次压缩、逐字保留跌至 ~3.9K token。
   ⇒ **不采纳**，登记为「端点持续 0 命中时的应急档」。
5. **新增主导可控变量：会话龄期**（本 ADR 未覆盖）。真 miss 按「距上次前缀改写的时间」分层：
   <10min 11–20%、10–60min 20%、>60min **45%**；会话首 13 步（gen0，无 prune）真 miss **0%**。
   ⇒ 下一步应做「及时新开会话（≤40 步 / ≤60 分钟）」的对照实验，而不是继续下调阈值。
   同时修正 v4 建议 2：前缀改写点之后 60s 内按 `cacheRead` 判 80% miss，按墙钟只有 20%（≈基线）
   ⇒「保持前缀稳定」的收益被高估。
6. **端点状态反向劣化（触发复审条件 1 的反向情形）**：同日 16:1x–16:3x 复测 `cached_tokens` 上报命中
   **0/22**（上午同协议可命中 25,088/25,274），未缓存预填充由 2,244 tok/s 掉到 **523–832 tok/s**，
   并出现单次 >300s 读超时；阳性对照 MiniMax-M3 同协议 `cache_read=24,470`、warm 2.1s / probe 1.3s。
   ⇒ 端点更差而非更好，0.2 档比原推理**更必要**；同时 `100 步 TTFT 地板 2,150s` 应按实测更新为
   **每步固定税 22–27s**（与 prompt 规模无关，`r(uncached, TTFT)=−0.076`），要突破它只能减步数或换端点。

  （**已被仓库内可复现工具取代**：`docs/ai-workspace/tools/agnes-cache-probe/`）

## 复审记录 2026-09-20R2（同日追加，Decision 不变）

**结论：维持 `thresholdRatio: 0.2`。** 本轮用 `docs/ai-workspace/tools/agnes-cache-probe/` 重跑判读并加做在线探针，
对本 ADR 的三条证据做确认/修正，均未改变「不恢复到 0.7」的判定。

| 项 | 本 ADR 原判 | R2 复核结果 |
|---|---|---|
| 证据 1「miss 与 prompt 规模无关」 | r=-0.035（跨世代混合样本） | **在同一 header 世代内独立复现**：gen1（n=71，prompt 161K–438K）r(规模,真miss)=**+0.039** |
| 证据 2「后端不一致」 | 由 `cacheRead` 双峰推断 | **机制坐实**：`cacheRead` 100/100 为 **256 整数倍**；命中步 `cached(k)≈prompt(k-1)`（失配中位 −0.55% ⇒ 严格链式）；同一世代内 miss 步同时出现 `2,304` 与 `7,936` 两种残值 ⇒ 分歧点不固定，客户端无法解释 |
| 证据 2「客户端不可控」（被否决备选：粘性路由/缓存亲和） | 断言客户端不可控 | **升级为实测**：`Server: cloudflare` + `CF-RAY *-CZX`；同一 TCP 连接内 CF-RAY 尾标识恒定、换连接即变；`api.agnes-ai.cn` 单 A 记录（anycast）；同连接同 payload 间隔 45s 复测仍 `cached=0` ⇒ 客户端唯一能钉住的是 Cloudflare 边缘节点，钉不住源站实例 |
| miss 率 41% | 按 `cacheRead<20K` | **降为上界**：加墙钟双判据后真 miss = **35%**（6 步属"命中但 `cached_tokens` 未上报"，5 步属"命中但排队慢"）。方向不变，收益估算偏保守 6pt |
| v4 建议「保持前缀稳定」 | 列为治本手段之一 | **收益被高估**：前缀改写点（header 世代切换 / 41 次 prune 爆发）后 60s 内按 `cacheRead` 判 80% miss，按墙钟仅 **20%≈基线** ⇒ 多数是计量假象 |

**新增主导变量（可控）：会话龄期。** 距上次前缀改写 >60min 的 67 步真 miss **45%**；<10min 的 23 步 **11–20%**；
gen0（会话首 13 步，无 prune）真 miss **0%**。⇒ 对症动作是**及时新开会话（单会话 ≤40 步 / ≤60 分钟）**，而非继续下调阈值。

**阈值寻优（同公式复现，误差 ≤5%）：** `0.06/4096`→2,214s、`0.05/3072`→2,166s（vs 当前 `0.2/32768` 3,260s，约 −34%），
但收益随 miss 率消失（miss 5%→−5.0%，miss 0%→−0.8%），且代价为每 5–8 步一次压缩、逐字保留跌至 ~3.9K token。
⇒ **不采纳**，仅登记为「端点持续 0 命中时的应急档」。

**端点状态变化（影响复审条件）：** 同日 16:1x–16:3x 复测，22/22 次探针 `cached_tokens=0`（上午同协议可命中 25,088/25,274），
110K 请求 warm 214.1s、probe 30.8s、probe2 >300s 读超时（预填充由 2,244 tok/s 劣化至 523–832 tok/s）；
同 payload 同连接墙钟 1.60s/6.26s/16.76s（10× 抖动）。
⇒ 触发复审条件 3 的精神（端点行为发生量级变化），但方向是**恶化**，故 0.2 档比原推理更必要；
同时新增判读纪律：**`cached_tokens` 不可单独作判据，必须与墙钟对照**。
