# 切片治理 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 六个切片按依赖依次落地，每切独立分支独立验收，任一切可回退。

**Architecture:** 切片即分支，门即验收，证据入库，前置不满足记顺延。

**Tech Stack:** Python、PowerShell 7、Git 功能分支加合请求。

**对应规格：** `docs/superpowers/spec/切片治理设计规格-v1.0.md`

---

### Task 0：P0 收尾（合入裁定）

**Files:** none modified (record only)

- [ ] **Step 1: 确认云端状态**

合请求检查全绿且零新增红（相对主干底红），则按既有决议合入；否则列新增红逐项修后再合。

- [ ] **Step 2: 落分支记录**

合入后切回主干，工作区脏物核对（别人的半截活原样保留）。

### Task 1：P1 原子收编

前置：原作者确认或 owner 裁定（未裁定本任务整体顺延）。

**Files:**
- Adopt: `.harness/scripts/validate-task-card.py`

- Adopt: `.harness/tests/` 相关测试与生成器
- Fix: 生成器模板范围重叠

- [ ] **Step 1: 逐文件审阅半截活**

通读每一处增删，删减逐条定性（放宽或收紧），收紧处必须有对应测试，记录审阅结论。

- [ ] **Step 2: 原子提交**

同一提交内落地全部文件，不拆散；提交信息注明收编来源与审阅结论。

- [ ] **Step 3: 三向验证**

clean 检出校验全绿；回归数只增不减；故意造红卡（野路径野门禁重叠范围）仍红。三项证据入库。

### Task 2：P2 验证转正

前置：P1 落定。

- [ ] **Step 1: 定主人定到期日**

覆盖率变异阈值各定主人与转正日期，写入配置注释。

- [ ] **Step 2: 补差分脚本**

补齐缺失脚本，本地演练红绿各一次。

- [ ] **Step 3: 转阻断**

去掉观察期开关，云端故意造一次下滑验证拦截并留审计记录。

### Task 3：P3 评审汇报线

前置：P0 合入加 P2 转正。

- [ ] **Step 1: 评审角色只读上线**

独立评审只挑刺不放行，跑三单留记录。

- [ ] **Step 2: 证据改附件**

测试证据改云端附件，汇报自检表上线。

- [ ] **Step 3: 分级自动合入**

小改动自动合，大改动留人，连续多单无人点头验收。

### Task 4：P4 规划层

- [ ] **Step 1: 依赖图检查上线**

环悬空覆盖三项，旧卡豁免清单冻结，新卡违规变红。

- [ ] **Step 2: 双向链接与契约冻结**

需求到卡双向可查，接口契约先行，生成器谓词化。

- [ ] **Step 3: 占位清零**

存量占位逐张消，新卡无占位引用。

### Task 5：P5 装箱减法

前置：工程完工。

- [ ] **Step 1: 技能三件套**

通用做法装箱，项目专属留适配层，按写技能规矩做失败测试。

- [ ] **Step 2: 知识减法与查询开放**

地图化，账本对干活者开查询，新仓库一天接入验证。

### Task 6：总验收
