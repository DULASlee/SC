# 切片治理 设计规格 v1.0

- 日期：2026-10-16
- 状态：待审批（未执行）
- 依据：技术方案说明书第四章十项缺陷、专家切片治理参考意见
- 总原则：不推翻底层架构，补门补位补主人，风险闭环导向

## 1. 目标与非目标

目标：六个切片依次落地，每切有验收有主人，任一切回滚不伤他切。非目标：不换架构，不重写流水线，不动业务代码。

## 3. 每切片设计

### P0 安全防线与归属对账切片

内容：归属三口子收紧、范围变严、命令对账、体检进云端、推送门禁、复用认主人、回归小修，共十七项新增测试。验收：云端全绿加零新增红。风险：主干底红，需 owner 按既有决议裁定合入。回退：功能分支整体回退，不影响主干。

### P1 校验器原子收编切片

内容：放宽校验器、配套模式、登记表、测试、生成器作为原子单元审完测完一次入库，生成器模板范围重叠同修。红线：任何情况下不删测试不降门槛，别人的半截活原样保留直到收编。验收： clean 检出校验全绿，回归数只增不减，故意造红例仍红。前置：原作者确认或 owner 裁定收编，未裁定不动手。

### P2 验证转正与质量门切片

内容：覆盖率变异阈值定主人定到期日转阻断，补差分脚本，分阶段开可靠性容器，空工程政策执行。验收：阈值拦住过至少一次真实下滑且留审计记录。依赖： P1 落定。

### P3 机器评审与汇报线切片

内容：独立评审角色只挑刺不放行，测试证据改云端附件，完成汇报对预期自检表，全绿自动合入按分级生效，人只看汇报与异常。验收：连续多单无人点头，汇报讲清干了什么凭什么算过。依赖： P0 合入加 P2 转正。

### P4 规划层规范化切片

内容：依赖图环悬空覆盖检查，需求到卡双向链接，接口契约先行冻结，生成器谓词化只写规格契约验收测试，卡由脚本生成。验收：占位卡清零，新卡无占位引用。相对独立可并行，建议 P3 后。

### P5 技能装箱与知识减法切片

内容：通用做法装技能集三件套，项目专属留适配层，知识库做减法成地图，账本对干活者开查询。验收：新仓库一天接完，三会话并行互不干扰有证。收尾，必须工程完工后。

## 4. 依赖链与推进策略

P0 无依赖待裁定合入。P1 需裁定。P2 严格依赖 P1。P3 依赖 P0 合入加 P2 转正。P4 可并行建议 P3 后。P5 收尾。任一切入口先验前置，前置不满足记顺延不硬上。

## 5. 全局验收与回退

每切独立分支独立合请求，验收证据入库对应目录，任一切失败回退本切不碰他切。跨切冲突（同一文件两切都要改）以后切为准，先切只读后切重验。

## 6. 自检记录

- 占位扫描：无待定事项，验收均可执行
- 一致性：切片与缺陷映射全覆盖，无重叠无遗漏
- 范围：单规格管六切，不扩散到业务
- 歧义：裁定主体明确为原作者或 owner ，过渡开关语义沿用既有约定

## 7. 全局约定（配合实施计划 v2）

- 主干即 main 分支，主远端即 origin，合请求即 GitHub PR。
- Owner 即项目负责人，书面裁定即对话原话引用存档为 ruling.md 文本。
- 证据根为 .harness/evidence/p0 到 p6，切片关闭以 CLOSED 文件存在为准。
- 运行环境为 Windows 加 PowerShell 7 加 Python，子进程指定 utf-8 编码。
- 临时物只允许放在对应证据目录 tmp/ 子目录下，用完删除。
