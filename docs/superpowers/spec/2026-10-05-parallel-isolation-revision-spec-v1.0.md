# 并行隔离段修订 设计规格 v1.0

- 日期：2026-10-05
- 状态：待审批（未动代码）
- 范围：仅多会话并行隔离段的修订完善；自动验证转正、机器评审、汇报线、自动拆卡走后续段，本规格不动
- 约束（已确认）：存量上改，不重建；全绿自动合入是终态（合入策略见段 D，本规格只把“绿”的可信度做实）；技能集装箱等工程完工后再做

## 1. 背景

隔离骨架真实存在且箱内验证全绿（见技术手册第六章），但三处结构性口子、两处放水、多处漂移与文字债使“互不干扰”不可信（见技术手册第七章）。本规格把已定位的缺口逐项转为可验收的修订需求。

## 2. 修订需求

### F1 提交验身份（严重）

现状：归属门禁只查工作树有没有主人，不比对提交者。修订：提交时比对提交者与登记主人，不一致拒绝。手工会话人名以领卡时登记为准；机器会话以派发身份为准。误伤预案：同一人名换机器需先释放重领（已在手册 8.2）。

### F2 主树提交管制（严重）

现状：主树提交无条件放行。修订：主树提交同样要求归属（主树任务需领卡）或白名单路径（经审批的直改），默认拒绝。调度器自身的卡状态提交走白名单（凭任务卡自覆盖契约）。

### F3 云端等价归属检查（严重）

现状：跳过钩子推送后云端无归属检查。修订：云端检查新增一项——推送分支的提交若来自他人工作树绑定任务且无释放记录，判失败。只读账本与归属登记，不写任何状态。

### F4 多卡时本地范围检查变严（重要）

现状：活动卡非唯一即警告跳过。修订：非唯一时必须显式传卡号，否则拒绝（返回失败），指引打印领卡与查卡命令。空暂存仍警告过。

### F5 测试命令对账（重要）

现状：云端命令顶层与冻结口径漂移。修订：二选一收敛（以冻结口径为准），并附一次对账证据（两边分别跑出的用例数一致）。此后任一改动须同步两处。

### F6 并发体检进自动门（重要）

现状：三区三进程体检只能手工跑。修订：接进云端检查成为独立任务，跑全 V1-V10；动锁与归属文件的变更必须触发它。超时与 Windows 进程判活沿用现有实现。

### F7 推送门禁拒绝直推与强推（重要）

现状：直推主干仅提醒。修订：推送门禁拒绝直推主干与开发干，拒绝强制推送任何分支（去污场景走“删分支重建”替代强推，手法不变、风险点消除）。功能分支普通推送不受影响。

### F8 复用认主人（重要）

现状：工作区目录已存在即直接复用，不验主人。修订：复用前比对目录归属记录：同主人或已释放可复用并重绑；他人持有则拒绝并指引。文件级写入仍为事后门禁（提交时拦），本规格不做文件系统强制（代价过大，收益小）。

### F9 补回归与修验收小错（中）

换行规范与提交路径限定各补一条回归测试（故意造脏文件、故意混暂存，门禁必须变红）；验收脚本缺导入导致特定放行旗必错，补导入。空测试工程要么补用例要么下线，二选一，不留占位。

### F10 线上点火（条件项）

真探针、在线三并发全链、崩溃恢复全链、常驻实跑。前置：模型线路可用。若前置不满足，本项自动顺延，不阻塞 F1-F9 合入。

## 3. 非目标

- 不改卡字段、不改状态机、不改分支命名、不改双账本结构
- 不删历史分支与手工树（只认主人不清错）
- 不碰自动拆卡、机器评审、汇报线（后续段）
- 不把覆盖率变异阈值转正（属验证段，后续段；但 F5 对账时如实记录现状）

## 4. 验收标准

- A1：三口子各有一条红态证据（冒名提交、主树直交、绕过钩子推送分别变红），绿态正常放行
- A2：多卡并行下不传卡号提交变红，传对卡号放行
- A3：云端命令与冻结口径一致，对账证据入库
- A4：并发体检在云端检查里可查到最近一次全绿记录
- A5：直推主干与强推在推送门禁变红，功能分支推送不受影响
- A6：全部已有回归用例数不减少（只增不减），提交门禁全套通过
- A7：F10 若前置满足则留证，若不满足则有顺延记录，不硬上

## 5. 风险与回退

- 身份比对可能误伤合法场景（如同一人多机）：预案为释放重领流程，风险低
- 主树管制可能拦住调度器自身提交：白名单覆盖派发占坑与状态提交，已在 F2 列明
- F7 去强推改删建：去污手法多一步，安全换便利，值
- 回退：全程功能分支，任一验收失败回退该任务文件；门禁类变更先只告警一轮再转拒绝（过渡期一次）

## 6. 自检记录

- 占位扫描：无 TBD/TODO，每项都有明确行为与证据要求
- 一致性：F1-F3 对应三口子，F4-F9 对应放水漂移残留，F10 为条件项；非目标与后续段无重叠
- 范围：单段修订，不扩散到验证转正与评审员
- 歧义：“提交者”定义为领卡登记身份，非操作系统用户；“主树”以公共目录父目录为准，与现有门禁一致
