## 1. 背景与问题

近期四个工具调用大模型时频繁出现低级逻辑错误。磁盘取证（本会话 fresh evidence）结论：

- 用户自维护的两个自定义模型清单中，共 22 条目全部缺失发散程度与思考深度声明（0/22），设置文件亦为 0 条相关调节；
- 长度声明方面：WorkBuddy 22 条全齐；CodeBuddy 22 条中 6 条缺失长度声明（缺失项会掉进默认兜底）；Codex 官方目录默认思考档为 high 且支持 low/high/max（或 none/high）；
- Qoder 本地无可调模型参数，为平台托管；
- 运行痕迹显示真实调用可达 84 万字级输入，说明长链路任务中长度截断与思考档回落是主要嫌疑。

## 2. 目标与非目标

目标：
- G1：全部自定义模型补齐最高思考档声明，杜绝回落到中间档与关闭思考；
- G2：逐模型核对上下文长度，使自定义清单与官方目录一致，缺失项补齐，代理通道与直连通道差异显式标注；
- G3：四工具行为一致：默认深入思考开、强度最高、长度不丢；
- G4：千问与火山两家主力模型在四工具内可用（含 Codex 缺失的千问通道与 deepseek-v4-pro 目录条目）。

非目标：
- 不调整提示词、工具编排、压缩策略；
- 不缩小生成长度上限；
- 不做模型本身的基准跑分（本规格只保证参数透传正确）。

## 4. 思考档设计（全部最高）

- 原则：有 max 用 max，无 max 用 high；禁用 none/off；发散程度保持默认 1（不为了快而关思考）。
- WorkBuddy/CodeBuddy 自定义条目：每个条目新增仅推理相关声明 effort=最高可用档、summary=auto；能声明仅推理的纯推理模型加 onlyReasoning=true。
- Codex：全局推理强度保持 high；凡支持 max 的模型允许按任务升到 max；MiniMax-M2.7 仅支持 high，不可强写 max。
- Qoder：本地无参数位，规格要求在工具内选择最高档模型并确认深入思考开关为开，留存截图/导出作为证据。

## 5. 四工具改动面

- WorkBuddy：补自定义清单全部条目的思考档声明；长度已齐，仅复核代理/直连两条 DeepSeek 差异备注。
- CodeBuddy：补 6 条缺失的长度声明（以本次核对为准：M2.5 高速版、M2.7、M3、主力代码模型、2.0 迷你版、视频模型） + 全部 22 条的思考档声明；补 variantModels 指向已核对模型。
- Codex：config 保持 high；mmx 目录补 deepseek-v4-pro 条目（上下文 1048576，档位 low/high/max，默认 high）；新增千问供应商通道（与火山/DeepSeek/MiniMax 并列），密钥沿用现有注入方式，不在文档中明文抄录。
- Qoder：不写本地文件，输出一份对照确认单（模型→档位→长度→开关状态）。

## 6. 验收标准

- A1：复核脚本显示四工具自定义条目思考档声明覆盖率 100%，无 none/off；
- A2：复核脚本显示长度缺失数为 0，且与第 3 节基准表逐项一致（含 204800 与 200000 两档不得放大）；
- A3：Codex 千问通道连通性探针通过（不跑大模型问答，只做轻量连通）；
- A4：备份齐全（每个被改文件带时间戳备份），可一键回退；
- A5：全程只改配置与文档，不入库任何真实密钥。

## 7. 风险与回退

- 风险1：最高档延迟与费用上升。缓解：先灰度一个工具验证体感，再全量。
- 风险2：max 档在部分模型上不可用导致调用被拒。缓解：规格已限定“有 max 用 max、无 max 用 high”，实施时逐条按官方目录 levels 校验。
- 风险3：代理通道实际窗口小于标称。缓解：备注代理差异，验收时以实测截断为准，必要时下调该条。
- 回退：每个文件修改前备份，任一验收失败即还原该文件并记录。
